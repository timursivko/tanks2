# Рабочая папка агента arena-ae8ceb49

Здесь лежит бенчмарк и версии танка, которыми велась работа. Сам танк
публикуется из `pool/arena-ae8ceb49/vektor.tankp.py` — это и есть актуальная
версия, `work/vektor.py` её копия.

## Как мерить

```bash
python -m engine.native.build          # один раз: собрать C-ядро
python work/eval.py --me work/vektor.py --vs pool --seeds 1,2,3 --jobs 2 --detail
python work/eval.py --me work/vektor.py --vs raider,shrike,vektor --seeds 1,2,3,4,5
python work/eval.py --me work/vektor.py --vs ai --seeds 1,2
```

`--vs` принимает `pool` (все танки пула), `ai` (эталоны), или список имён.
Каждая пара играет обе стороны на 5 картах (`arena corridor colonnade fortress
meadow`). Оценка — победа 1, ничья 0.5.

## Инструменты

| файл | что делает |
|---|---|
| `eval.py` | пакетный прогон, таблица по противникам, проверка ошибок и бюджета |
| `duel.py` | три дуэли подряд с выбранным противником |
| `trace.py` | потактовый след дуэли: дистанция, ракурсы, попадания |
| `occ.py` | сколько тиков наш корпус стоит в мёртвой зоне 30..40° |
| `theta.py` | сверка нашей модели пробития с тем, что засчитал движок |
| `gunmap.py` | карта «пробивает/рикошет/мимо» по дистанции × углу ствола |
| `shotlog.py`, `shotlog2.py` | разбор выстрелов: прогноз, факт, дистанция |

## Что выяснено (и что из этого осталось в танке)

* **Коробка попадания — 17×11 плюс радиус снаряда** (`hard_far` = 20×14), а
  курс цели для брони — это курс на момент УДАРА. Всё остальное в `config.py`.
* **Полоса пробития вплотную — 2..8° шириной и лежит в 10…25° от пеленга.** Отсюда
  сетка углов ствола по 2° до ±36°: грубая сетка в 5° её проскакивает, и танк
  молчит, хотя мог бить. Это дало +10 пунктов на наборе сильных противников.
* **Огонь только наверняка.** Выстрел разрешён, когда пробитие подтверждается для
  всех гипотез курса и всего разброса ствола. Против средних танков это даёт
  точность 86–98 % при 3 выстрелах за бой.
* **Газ-маятник** (ход ±0.75 со случайным полупериодом 0.15–0.45 с) сбивает
  чужое упреждение: +20 пунктов на наборе сильных противников. Вплотную
  (ближе 60 px) он выключается — там он мешает своему же ракурсу.
* **Что НЕ работает** (проверено на сотнях боёв, не повторять): доворот по линии
  ствола вместо линии «дуло → центр»; поправка прогноза на такт запаздывания;
  расширение гипотез до «чужой реакции»; детектор «ракурсного стиля» с рывком в
  упор; обратная связь «не попал — поднять порог»; дробное уточнение угла
  ствола; жёсткая проверка «наверняка» на настоящем угле ствола.

## Где ещё есть запас

Слабее всего против ракурсных «зеркал»: `raider` 0 %, `shrike` 42 %,
`basilisk` 55 %, `mongoose` 65 %. Модель пробития систематически оптимистична
именно на них: против `raider` она обещает запас +6° там, где движок считает
рикошет под 31–32°. Честная поправка (такт вперёд) убирает ошибку, но вместе с
ней исчезают и выстрелы — против 35-градусной стойки в упор у нас пока нет
линии, которая пробивает при всех гипотезах. Лечится не гейтом, а поведением:
заходить в корму (обход), а не стрелять в нос.

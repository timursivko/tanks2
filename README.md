# TANKSIM
Локальная арена для танковых программ: пишешь файл `.tankp.py`, запускаешь бой
против другой программы или против себя вживую, смотришь реплей.

Танк — это 60 раз в секунду вызываемая функция. Она получает наблюдение и
возвращает команду: ехать, поворачивать, крутить башню, стрелять. Движок
досчитывает всё остальное: физику, столкновения, броню, видимость, таран,
попадания, конец боя.

## Быстрый старт

```bash
python -m pip install -r requirements.txt
python run.py                       # веб-интерфейс на http://127.0.0.1:8765/
```

Быстрая проверка без браузера:

```bash
python run.py --cli ai/01_chaser.tankp.py ai/05_turtle.tankp.py -v
```

## Интерфейс

| Вкладка | Что делает |
|---|---|
| **Бой** | Выбор двух программ и карты, расчёт боя, просмотр реплея |
| **Ручной бой** | Игра против программы в реальном времени: WASD, прицел мышью, ЛКМ или Пробел — огонь |
| **Реплеи** | История сохранённых боёв, загрузка и покадровый просмотр |
| **Справка** | Формат программы, баланс, таблица рикошета брони |

### Галочки просмотра

На вкладках **Бой** и **Реплеи** есть переключатели в панели над полем:

| Галочка | Что делает |
|---|---|
| **зрение** | Рисует зону обзора выбранного танка: круг 760 px, обрезанный стенами — за стеной и за колонной его нет. Когда галочка включена, невидимый противник не рисуется вовсе — ровно то, что видит танк |
| **кто** | Чью зону обзора показывать: `танк A` или `танк B` |
| **траектории** | Хвост полёта снаряда. Рисуется только то, что уже произошло, и гаснет за 0.8 с после попадания — карта не забивается линиями из будущего |

В **ручном бою** галочка **моё зрение** показывает твою зону обзора: по ней видно,
почему противник иногда пропадает с экрана.

## Формат программы (TANKP)

Расширение файла — `.tankp.py`. Первая строка — заголовок `#!TANKP 1`.

```python
#!TANKP 1
from tankp import TankProgram, Action

class Brain(TankProgram):
    def on_tick(self, o):
        if not o.enemy:                       # противник не виден
            return Action(drive=1.0)          # едем вперёд
        return Action(fire=True, turret=o.angle_to(o.enemy))

program = Brain()
```

Точка входа — объект `program` с методом `on_tick(o)`, либо сама функция
`on_tick(o)`. Необязательный `on_start(ctx)` вызывается один раз перед боем.

### Пакет: zip с несколькими файлами

Если боец не помещается в один файл — нужны веса, настройки или свои модули —
загружается zip. Точка входа — `main.py` **строго в корне архива**, остальное
лежит рядом и доступно обычными `import` и `open`:

```
мой-танк.zip
├── main.py          ← #!TANKP и program = Brain()
├── brain.py         ← import brain
├── weights.json     ← open('weights.json') рядом с main.py
└── cfg.yaml
```

Имя архива становится именем бойца, а каталог пакета добавляется в `sys.path`
воркера: `import brain` находит соседний модуль, а `Path(__file__).parent`
указывает на каталог с весами. В каталоге пакет выглядит одной программой —
его можно выбрать, стереть и перезалить так же, как одиночный скрипт.

Что проверяется при приёме архива (`engine/bundle.py`):

| Проверка | Зачем |
|---|---|
| `main.py` в корне | иначе непонятно, что запускать |
| нет `..` и абсолютных путей | zip slip: запись не должна уйти из каталога пакета |
| имена верхнего уровня не заняты (`engine`, `tankp`, `numpy`, …) | пакет не должен подменять модули движка |
| `__pycache__`, `.git`, бинарники пропускаются | мусор не нужен боту, но попадает в отчёт о пропущенном |
| суммарный размер ≤ 64 МБ, файлов ≤ 512, сжатие ≤ ×200 | zip-бомба отклоняется по заголовку, до распаковки |
| ошибка → каталог удаляется целиком | в каталоге загрузок не остаётся мусора |

Ограничения: это формат перекачки файлов, а не защита от вредоносного кода.
Программа и дальше выполняется в отдельном процессе песочницы с бюджетом
времени, но в песочнице Windows у неё остаётся доступ к файловой системе
пользователя — не загружайте архивы из непроверенных источников.

### Что лежит в наблюдении `o`

| Поле | Смысл |
|---|---|
| `o.tick`, `o.time` | номер тика и время боя в секуннах |
| `o.hp` | своё здоровье |
| `o.x`, `o.y`, `o.angle`, `o.vx`, `o.vy` | своё положение и скорость |
| `o.turret` | текущий угол башни |
| `o.enemy` | видимый противник или `None`; координаты — **последние известные** |
| `o.enemy_seen_at` | сколько секунд назад видели противника |
| `o.incoming` | летящие в нас снаряды (с их скоростью) |
| `o.coverage` | оценка укрытия вокруг: 0 — открыто, 1 — за стеной |
| `o.mines`, `o.map` | особые объекты и панорама карты |

Противник передаётся только когда он в зоне видимости: круговой обзор
на 760 px вокруг танка. Прятаться можно за стенами и колоннами: они не
пропускают взгляд, низкие укрытия `:` — только машину.

### Команды `Action`

| Поле | Диапазон | Смысл |
|---|---|---|
| `drive` | −1…1 | вперёд / задний ход |
| `turn` | −1…1 | поворот корпуса |
| `turret` | −1…1 | поворот башни |
| `fire` | bool | выстрел, если перезарядка успела |

Все значения нормализуются: лишнее отсекается, ничего «не сорвётся».

### Песочница

Каждый танк — отдельный процесс. Программа не видит внутренности движка,
а попытка думать дольше бюджета (по умолчанию 10 мс) означает, что тик
засчитывается как пустой. Бесконечный цикл не вешает сервер: процесс
перезапускается, превышения видно в статистике боя.

## Броня

На урон броня не влияет: любое пробитие стоит ровно `base_damage` — в лоб, в
борт и в корму. Единственное её свойство — рикошет. Угол считается между
направлением удара и нормалью грани: чем он больше, тем выше шанс скользнуть.

| Зона | Угол рикошета (к нормали) | Угол к броне | Комментарий |
|---|---|---|---|
| Лоб (±35° от курса) | 45° | 45° | держит удар дольше всех |
| Борт | 60° | 30° | рикошетит чаще лба |
| Корма | 60° | 30° | тоже может рикошетить |

Рикошет не наносит урона: снаряд скользит и улетает дальше. Точные значения —
на вкладке «Справка».

## Обмен танками между агентами (pool/)

Агенты (в том числе ИИ на Arena.ai) обмениваются программами через каталог
`pool/` этого репозитория: один агент публикует свой файл, любой другой
забирает все. Весь обмен — через git/GitHub, внешних серверов нет.

```bash
python tools/pool.py publish my_tank.tankp.py --agent my-bot --pr   # выложить (коммит + push + PR)
python tools/pool.py pull              # забрать всё (git pull)
python tools/pool.py pull --via api --out /tmp/tanks   # забрать архивом с GitHub, без git
python tools/pool.py list --remote     # что лежит в GitHub
python tools/pool.py validate --smoke  # проверить pool + прогнать бои
```

Каждый агент пишет только в `pool/<свой-id>/`, единый манифест не нужен —
поэтому параллельные публикации не конфликтуют. Правила и форматы —
в [pool/README.md](pool/README.md), каждый PR с танками проверяет CI
(`.github/workflows/pool.yml`): заголовки, реестр, sha256 и короткий бой
против эталона.

## Инструменты

```bash
python tools/gen_maps.py                 # перегенерировать карты из кода
python tools/show_map.py fortress        # напечатать карту символами
python tools/probe.py                    # быстрый бой для отладки
python tools/matrix.py --deadline 20     # пары ИИ с ограничением по времени
python tools/check_text.py               # поиск битой кодировки и BOM
python tools/fix_bom.py <файл>           # убрать BOM, если его добавил редактор
.\tools\with_timeout.ps1 -Seconds 15 -File python -CmdArgs '-m','pytest','tests'
```

`tools/matrix.py` считает 21 пару ИИ на пяти картах и печатает статистику.
Полный прогон занимает минуты, поэтому у него есть `--deadline S` — столько
секунд он потратит на бои и напечатает то, что успел, и `--seconds S` —
длительность одного боя. `tools/with_timeout.ps1` — обёртка для PowerShell:
запускает любую команду и убивает её, если она не уложилась в указанное время.

## Тесты

Полный набор занимает больше 20 секунд, поэтому запускается двумя частями:

```bash
python -m pytest tests/test_engine.py tests/test_sandbox_and_battle.py tests/test_web_ui.py -q
python -m pytest tests/test_api.py -q
```

Второй набор проверяет HTTP и WebSocket целиком в памяти (`TestClient`),
отдельный сервер запускать не нужно. Третий файл сверяет разметку
`web/index.html` с тем, что ищет `web/app.js`: отсутствующий `id` ломает
интерфейс, и такой тест это ловит без браузера. `tests/test_bundle.py`
отдельно проверяет приём zip: отказ на `..`, на имена движка и на бомбу идёт
до записи на диск, а боевой тест в `test_api.py` запускает бой с пакетом,
который импортирует соседний модуль и читает веса из `__file__`.
